# Visual Dashboard System

> 销售数据可视化看板生成系统 — 从原始 Excel 到 6 页交互式 HTML 看板的自动化流水线

---

## 快速开始

```bash
# 安装依赖
pip install -r requirements.txt

# 预检（确认数据就绪）
python main.py --dry-run

# 全流程一键运行
python main.py

# 或 Windows 双击
run_all.bat
```

> 详细部署说明请参阅 [docs/部署指南.md](docs/部署指南.md)

## 打包交付

```bash
# Windows 用户双击即可
package.bat

# 生成 Visual-Dashboard-System_vYYYYMMDD.zip
# 包含全部代码 + 配置 + 目录骨架，不含敏感数据
```

## 配置指南（数据更新必读）

### ⏱ 时间范围

**文件**：`config/清洗配置/cleaning_config.json` → `时间范围`

更新数据后，**只需改这个文件**的日期，重新运行即可：

| 配置项 | JSON 路径 | 示例值 | 影响页面 |
|--------|-----------|--------|----------|
| 年度累计 | `时间范围.年度累计` | `2026-01-01 ~ 2026-08-31` | 数据总览 / 年度达成 / 销售达成 / 年度同比 |
| 月度数据 | `时间范围.月度数据` | `2026-08-01 ~ 2026-08-31` | 月度达成 |
| 季度累计 | `时间范围.季度累计筛选` | `2026-07-01 ~ 2026-09-30` | 季度达成 |
| 年基线 | `时间范围.年基线数据` | `年份: 2025, 月份: [1, 8]` | 年度同比（Phase 0） |

改法示例：
```json
"时间范围": {
    "年度累计": { "start_date": "2026-01-01", "end_date": "2026-09-30 23:59:59" },
    "月度数据":  { "start_date": "2026-09-01", "end_date": "2026-09-30 23:59:59" },
    "季度累计筛选": { "start_date": "2026-07-01", "end_date": "2026-09-30 23:59:59" }
}
```

### 🎨 展示规则

**文件**：`config/前端渲染/展示规则.json`

| 配置项 | 说明 |
|--------|------|
| `*.优先展示` | 填母公司组名或客户名，始终排在前面（其余折叠到"查看全部"） |
| `*.最大行数` | `0` = 全部显示；`>0` = 截断到该行数 |
| `*.排序` | `目标合计降序` / `实际金额降序` / `达成率降序` |
| `*.销售TopN` | 数据总览/销售页中显示的最大销售人数 |

#### 1. 财务端收入 → `data/raw/财务端数据/收入.xlsx`

| 部门 | 成本中心.名称 → 成本中心 |
| 法人主体 | 公司 |
| 客户区域 | 客户.客户区域 |

#### 2. 财务端回款 → `data/raw/财务端数据/回款.xlsx`

ERP 系统导出，**当月单月**数据。金额单位：**元**。

| 通用列名 | Excel 候选列名 |
|----------|---------------|
| 日期 | 业务日期 → 收款日期 → 创建时间 |
| 客户 | 付款人(客户).名称 → 付款人名称 → 客户.名称 |

#### 3. 广东公司 → `data/raw/财务端数据/广东公司.xlsx`

独立格式，**金额单位万元**（系统自动 ×10000 → 元），部门固定 **"检测"**。

| 通用列名 | Excel 候选列名 |

#### 4. 湖南公司 → `data/raw/财务端数据/湖南公司.xlsx`

| 法人主体 | 法人主体 → 核算单位 |

#### 6. 运营端回款 → `data/raw/运营端数据/回款.xls`

| 通用列名 | Excel 候选列名 |
|----------|---------------|
| 日期 | 到款时间 → 确认时间 → 时间 |
| 客户 | 客户 → 客户名称 |

## 更新数据操作清单

每次拿到新一期 Excel：

1. **替换文件** → `data/raw/` 下对应 Excel（文件名保持不变即可）
2. **更新指标** → `data/sheets/手动维护/` 下 6 张表（列结构不变，改数值）
3. **修改时间** → `config/清洗配置/cleaning_config.json` 中 `时间范围` 的日期
4. **运行** → `python main.py`（或双击 `run_all.bat`）
5. **查看** → `output/看板/看板_YYYYMMDD.html` 浏览器打开

## 使用流程

### 1. 运行

```bash
python main.py                          # 全流程
python main.py --step=yearly            # 只年基线
python main.py --step=clean             # 只清洗 Phase 1+2
python main.py --step=split             # 只销售拆分
python main.py --step=render            # 只渲染
python main.py --type=收入              # 只收入链路
python main.py --from=clean --to=render # 区间执行
python main.py --dry-run                # 预检（不写文件）
python main.py --list                   # 列出所有步骤

# 调试用（等价于对应 step）
python -m engine.yearly_baseline.run
python -m engine.income_payment.run --type=收入
python -m engine.sales.run
python -m processors.run
```

### 2. 获取结果
- `output/看板/看板_YYYYMMDD.html` — 6 页可视化看板
- `output/数据/data_YYYYMMDD.xlsx` — 11 Sheet 数据总表

### 3. 运行测试

```bash
python -m pytest tests/ -v              # 101+ 用例
python -m pytest tests/ -k "splitter"   # 按关键字
```

## 4-Phase 流水线

```
Phase 0: 年基线清洗  →  往年收入/回款数据 → 往年收入/回款（6列标准表）
Phase 1+2: 收入/回款  →  财务端(当月) + 运营端(当年累计) → 三路输出（月/季度/当年累计）
Phase 3: 销售拆分    →  4层匹配 + 总额校验 → 销售收入/回款（7列）
Phase 4: 渲染看板    →  6页HTML + Excel总表 → output/
```

## 看板 6 页

| 页面 | 核心内容 |
|------|----------|
| 数据总览 | Hero 双环 + 事业部矩阵 + 销售 Top N |
| 年度达成 | Hero + 部门卡 + 客户达成矩阵(cell-bg) + 子公司弹窗（右侧抽屉） |
| 月度达成 | Hero + 部门卡 + 客户达成矩阵 + 子公司弹窗 |
| 季度达成 | Hero + 部门卡 + 客户达成矩阵 + 子公司弹窗 |
| 销售达成 | 卡片1:销售进度条 / 卡片2:销售×事业部矩阵 / 卡片3:销售×客户矩阵 + 右侧抽屉弹窗 |
| 年度同比 | 事业部同比表 + 客户同比矩阵（年基线无月份粒度时降级） |

## 核心设计

| 设计 | 说明 |
|------|------|
| 配置驱动 | 清洗参数全在 `cleaning_config.json`，页面/配色全在配置文件，改日期/列名不需改代码 |
| 列名映射 | 每个字段多个备选列名，按序尝试；**回款用应收金额、收入用不含税金额** |
| 单位转化 | 清洗引擎统一输出"元" → `_add_wan()` ÷10000 → "万元"展示 → `fmt_wan()` 千分位格式化 |
| 客户归拢 | 3+ 子公司自动聚合到母公司名，展示母公司维度；1:1 关系不聚合 |
| 子公司弹窗 | 点击母公司名 → 右侧滑入抽屉，展示子公司×4部门+合计的实际/目标/完成度 |
| 全局 .0f | 金额统一按万元取整无小数点 |
| 4层销售匹配 | 广东→深圳→其他规则→默认规则(统称继承)→待确认 |
