## 一、原始数据理解

### 1.1 数据源全景

系统从 **7 个原始 Excel 文件** 出发，分两大来源：财务端（ERP系统导出，当月全量）和运营端（运营系统导出，当年累计）。

```
data/raw/
├── 财务端数据/              ← ERP 系统导出，当月数据
│   ├── 收入.xlsx            ← 56列宽表，6月全量
│   ├── 回款.xlsx            ← 60列宽表，6月全量
│   ├── 广东公司.xlsx        ← 3列简表（收入/回款双Sheet）
│   └── 湖南公司.xlsx        ← 3列简表（收入/回款双Sheet）
├── 运营端数据/              ← 运营系统导出，当年截至上月的累计数据
│   ├── 收入.xls             ← 9列窄表，1-4月合计 + 5月
│   └── 回款.xls             ← 8列窄表，1-4月合计 + 5月
└── 客户名单/
    └── 客户名单.xlsx        ← 471个白名单客户
```

### 1.2 各数据源时间特性

| 数据源 | 时间范围 | 行数 | 金额合计 | 时间含义 |
|---|---|---|---|---|

| 广东公司收入 | 2025-07 ~ 2026-06 | 91 | 2.99万(万元) | **累计**简表（万元单位） |

| 湖南公司收入 | 2025-07 ~ 2026-06 | 78 | 0.32万(万元) | **累计**简表（万元单位） |

### 1.3 关键数据特征

**财务端**（收入.xlsx / 回款.xlsx）：
- ERP系统导出的**多列宽表**（56~60列），包含大量冗余字段
- 日期精确到**日**，是当月全量明细
- 金额单位为**元**（原始值，不÷10000）
- 含内部交易数据（需按硬编码名单排除3家公司）
- 客户名通过白名单过滤（471个白名单客户）

**广东/湖南公司**：
- 简单3列表格（客户/日期/金额），无部门列
- 金额单位为**万元**（与其他源不统一）
- 广东公司固定事业部为"检测"，湖南公司固定事业部为"信息"
- 广东公司不经白名单过滤（配置 `广东公司不经白名单: true`）

**运营端**（收入.xls / 回款.xls）：
- 9列窄表，结构简洁
- **时间粒度较粗**："1-4月"表示1月到4月的合计数据（不需拆分），"5月"为单月数据
- 金额单位为**元**
- 事业部列为**全称**（如"检测工程事业部"），需映射为简称
- 含内部交易标记列（`是否属于内部交易` / `是否属于内部款项`），按列值过滤
- 含 `法人主体` 列，用于广东/深圳公司识别

## 二、数据清洗流程

### 2.1 总体流水线

```
┌─────────────────────────────────────────────────────────┐
│ Phase 0: 年基线提取 (engine/yearly_baseline/)          │
│ 从历史年报表提取 2024/2025 年度数据作为同比基准         │
└─────────────────────┬───────────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────────┐
│ Phase 1: 财务端清洗 (engine/income_payment/financial.py)│
│ 收入.xlsx → 列提取 → 日期筛 → 内交排除 → 部门映射 →    │
│ 回款.xlsx → 列提取 → 日期筛 → 内交排除 → 部门映射 →    │
│ 广东/湖南公司 → 万元转元 → 固定事业部                   │
│ 全部 → 白名单匹配 → 标准化6列                           │
│ 输出: 财务端收入/回款（当月数据）                       │
└─────────────────────┬───────────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────────┐
│ Phase 2: 运营端清洗 (engine/income_payment/operations.py)│
│ 收入.xls → 列提取 → 内交过滤 → 部门映射 →               │
│ 回款.xls → 列提取 → 内交过滤 → 部门映射 →               │
│ 日期解析(保留"1-4月"/"5月"原文) → 广东/深圳识别          │
│ 输出: 运营端收入/回款（当年累计数据）                   │
└─────────────────────┬───────────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────────┐
│ Phase 1+2 合并输出                                      │
│ 三路输出（配置驱动）：                                   │
│   月收入/月回款        ← 仅财务端（当月）                │
│   当年累计收入/回款    ← 财务端 + 运营端（全量合并）     │
│   收入/回款            ← 同上（保持兼容）                │
└─────────────────────┬───────────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────────┐
│ Phase 3: 销售拆分 (engine/sales/splitter.py)            │
│ 收入/回款 → 4层匹配(广东→深圳→其他→默认→待确认)          │
│ 金额×比例拆分到销售 → 总额校验                           │
│ 输出: 销售收入/销售回款（含销售列，7列）                │
└─────────────────────┬───────────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────────┐
│ Phase 4: 渲染看板 (processors/)                         │
│ 7张数据表 → 5页HTML看板 → output/看板_YYYYMMDD.html     │
└─────────────────────────────────────────────────────────┘
```

### 2.2 数据时间层级关系

以当前数据（2026年6月）为例：

```
时间轴:  1月──2月──3月──4月──5月──6月
         │     │     │     │     │     │
运营端:  ├──────────────┤     │     │     │  ← "1-4月"合计(554行)
         │              │     │     │     │
         │              │     ├─────┤     │  ← "5月"(142行)
         │              │     │     │     │
财务端:  │              │     │     │     │  ← 6月(1359行)
         │              │     │     │     │
         └──────────────┴─────┴─────┴─────┘
 累计:   [============运营端累计==========]  ← 当年累计(696行)
 当月:                              [===]  ← 月数据(1359行)
```

**输出层级**：
| 输出文件 | 数据来源 | 用途 |
|---|---|---|
| `月收入/月回款.xlsx` | 仅财务端（当月） | 月度达成分析 |
| `当年累计收入/当年累计回款.xlsx` | 财务端 + 运营端 | 年度累计达成分析 |
| `收入/回款.xlsx` | 同上（兼容旧引用） | 渲染层主数据源 |

## 三、清洗逻辑详述

### 3.1 财务端清洗 (financial.py)

**步骤**：
1. **列名冗余提取**：按配置中的备选列名列表顺序尝试匹配
   ```python
   # 示例配置
   "列映射": {
     "日期": ["创建时间", "创建日期", "审核日期"],
     "客户": ["客户.名称", "客户名称", "客户.姓名"],
     "金额": ["含税金额", "含税金额总计", "金额"],
     "部门": ["责任部门.名称", "责任部门名称", "成本中心", "部门.名称"]
   }
   ```
2. **日期筛选**：按配置的 `财务端筛选` 时间范围过滤
3. **内部交易排除**：硬编码3家公司（广东汽车检测中心/中汽院深圳科技/中汽院湖南检测）
4. **金额保留原始值**：不÷10000
5. **部门映射**：统一使用回款版映射（50+条详细映射）
6. **白名单匹配**：只保留471个白名单客户
7. **标准化输出**：6列标准格式

**特殊处理**：
- **广东公司**：固定事业部="检测"，金额×10000（万元→元），标记 `是否为广东公司="是"`
- **湖南公司**：固定事业部="信息"，金额×10000（万元→元）

### 3.2 运营端清洗 (operations.py)

**步骤**：
1. **列名提取**：9列窄表直接映射
2. **内部交易过滤**：按 `是否属于内部交易` 列值过滤（`="是"` 的行排除）
3. **金额保留原始值**
4. **部门映射**：使用收入版映射（4条全名→简称）
5. **日期处理**：
   - 优先使用原始 `确认时间`/`到款时间` 列的值
   - 保留"1-4月"、"5月"等原文不变
   - 无法解析时回退固定日期
6. **广东/深圳公司识别**：
   - 检查 `法人主体` 列（或 `核算单位` 列）
   - 含"深圳"字样的标记为深圳公司
   - 含"广东"字样的标记为广东公司
7. **白名单匹配**：非广东/深圳公司的客户需通过白名单

### 3.3 合并逻辑 (run.py)

```python
# 三路输出
月数据 = 财务端数据（当月）
当年累计 = pd.concat([财务端, 运营端])  # 当年全部

# 写入
月数据 → data/sheets/月收入/月收入.xlsx
当年累计 → data/sheets/当年累计收入/当年累计收入.xlsx
当年累计 → data/sheets/收入/收入.xlsx（兼容）
```

### 3.4 销售拆分 (splitter.py)

**4层匹配规则**：
| 层级 | 规则数 | 匹配逻辑 |
|---|---|---|
| 广东公司规则 | 7条 | `是否为广东公司="是"` 的客户 |
| 深圳公司规则 | 2条 | `是否为深圳公司="是"` 的客户 |
| 其他规则 | 140条 | 按客户名精确匹配 |
| 默认规则 | 331条 | 统称名单兜底匹配 |
| 待确认 | — | 以上均未匹配的兜底 |

**金额拆分**：
- 金额 × 比例 = 拆分后金额（不四舍五入，保留完整浮点精度）
- 总额校验：拆分前总额 ≈ 拆分后总额（差异 < 1e-6 即通过）

## 四、标准输出格式

### 4.1 收入/回款（6列）

| 列名 | 类型 | 说明 |
|---|---|---|
| 事业部 | str | 检测/信息/能源/海外（已简称） |
| 金额 | float | 统一为元（广东/湖南万元→元已转换） |
| 客户 | str | 白名单匹配后的标准客户名 |
| 日期 | str | 财务端=原始日期，运营端="1-4月"/"5月"等原文 |
| 是否为广东公司 | str | "是" 或 空 |
| 是否为深圳公司 | str | "是" 或 空 |

### 4.2 销售收入/销售回款（7列）

6列 + `销售` 列（销售人员姓名，一行可拆为多行）。

### 4.3 输出目录结构

```
data/sheets/
├── 月收入/月收入.xlsx              ← 财务端当月收入
├── 月回款/月回款.xlsx              ← 财务端当月回款
├── 当年累计收入/当年累计收入.xlsx   ← 财务端+运营端（当年全部）
├── 当年累计回款/当年累计回款.xlsx   ← 财务端+运营端（当年全部）
├── 收入/收入.xlsx                  ← 同上（兼容）
├── 回款/回款.xlsx                  ← 同上（兼容）
├── 销售收入/销售收入.xlsx           ← 销售拆分后
├── 销售回款/销售回款.xlsx           ← 销售拆分后
├── 总指标/总指标.xlsx              ← 手工维护（年度目标）
├── 月度收入指标/月度收入指标.xlsx    ← 手工维护
├── 月度回款指标/月度回款指标.xlsx    ← 手工维护
├── 年收入/年收入.xlsx              ← 年基线
└── 年回款/年回款.xlsx              ← 年基线
```

## 五、配置驱动设计

全部清洗参数外置于 `config/cleaning_config.json`，包括：

| 配置段 | 内容 | 示例 |
|---|---|---|
| `数据源` | 文件路径、Sheet名、引擎类型 | `财务端/收入/文件名: "收入.xlsx"` |
| `列映射` | 标准字段→备选列名 | `金额: ["含税金额","金额"]` |
| `时间范围` | 财务端筛选、运营端固定日期 | `财务端筛选: {start_date, end_date}` |
| `输出` | 输出路径、标准列定义 | `收入: "data/sheets/收入/收入.xlsx"` |
| `客户匹配` | 匹配方式、不匹配处理 | `去空格模糊匹配: true` |
| `手工指标表` | 指标表路径 | `总指标: "data/sheets/总指标/总指标.xlsx"` |

## 六、已知问题与待办

| 问题 | 影响 | 状态 |
|---|---|---|
| 运营端日期粒度粗（"1-4月"为合并段） | 月度统计不精确 | 当前设计如此，不做拆分 |
| 广东/湖南公司金额单位（万元）与其他源不一致 | 渲染层需÷10000统一 | 已通过清洗阶段×10000解决 |
| 深圳公司识别依赖法人主体列包含"深圳"字样 | 可能漏识别 | 当前逻辑覆盖多数情况 |
| 待确认金额占比9.1% | 约3992万收入无法归属销售 | 需补充销售规则 |
| 36行负值收入(-999万) | 红字冲销，渲染层显示 | 正常业务，保留不处理 |
