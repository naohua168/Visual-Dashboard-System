# 代码结构与模块约定

> 2026-10-10 模块化重构后的目录约定、维护规则与验收方式。
> 重构原则：**只搬不写** —— 拆模块期间看板 HTML、数据总表、配置编辑器输出都逐字节比对过，行为零变化。

## 一、三层结构

```
原始数据(data/)  →  engine/（清洗引擎）  →  processors/（渲染层）  →  output/（交付物）
                        ↑                        ↑
                   config/*.json  ←────  scripts/（配置编辑器：Excel 编辑层 ↔ JSON 事实源）
```

- **engine/**：读原始 Excel、按配置清洗/归并/拆分，产出 `data/sheets/系统数据清理/`
- **processors/**：读清洗结果 + 配置，算页面数据、拼 HTML，产出看板与数据总表
- **scripts/**：把 Excel 编辑层与 JSON 事实源互转（含看板自检、销售汇总等工具）

数据只往一个方向流：原始 → 清洗 → 渲染。渲染层**不读原始表**，清洗层**不碰 HTML**。

## 三、模块约定

1. **对外接口**：包内 `__init__.py` 用显式 `from .x import a, b` + `__all__`；不要用 `import *` 扩散内部实现。
2. **兼容层**：重构后旧导入路径保留（`processors/page_data.py`、`page_data_utils.py`、`page_annual.py`、`scripts/config_excel_to_json.py`…），只做 re-export。
   - 新代码请从新包导入：`from processors.pages import AnnualPage`、`from processors.data_prep import prepare_annual_data`。
   - **状态转发**：兼容层用一个转发型模块类，让 `pdu._SUB_TO_PARENT = ...`、`cej.EXCEL_PATH = ...` 这类既有写法（测试/外部脚本）仍然生效；实现侧读的是子模块里的同名变量。
3. **模块级可变状态不可跨模块共享**：`_SUB_TO_PARENT`、`_SALES_SPLIT`、`_ATTRIBUTION_FLAT`、`_DOTTED_NAMES` 这类缓存，与"读写它的函数"必须在同一个子模块（跨模块重绑定模块级变量互不可见）。
4. **路径**：包内模块比原来多一层，`Path(__file__).parent.parent` 会失效。统一用
   `processors/data_utils/constants.py::PROJECT_ROOT`、`scripts/editor/paths.py::BASE_DIR`。
5. **命名**：包内模块名用语义（`consolidate` / `matrix` / `time_config`），类用 `XxxData`(数据) / `XxxPage`(页面)，私有工具加 `_` 前缀。
6. **样式/脚本改动**：只改对应的分包模块，不要在别处拼字符串；`static/css/` 与 `static/js/` 的拼接顺序不要调整。

## 四、常见改动去哪改

| 我要… | 改这里 |
|---|---|
| 改页面口径/取数 | `processors/data_prep/<页面>.py` |
| 改页面排版/文案 | `processors/pages/<页面>.py` |
| 改全局样式 / 表格样式 / Hero / 矩阵 | `processors/static/css/<对应模块>.py` |
| 改换页动效、表格折叠、Tab、导航 | `processors/static/js/<对应模块>.py` |
| 改归并/归属/法人过滤口径 | `processors/data_utils/consolidate.py` |
| 改指标/时间范围/透视排序 | `processors/data_utils/metrics.py` + `config/清洗配置/cleaning_config.json` |
| 改行业口径常量（母公司名、法人、部门、黑名单） | `config/清洗配置/业务规则.json`（代码里经 `engine/core/business_rules.py` 读） |
| 改 Excel 编辑层 ↔ JSON 的字段 | `scripts/editor/<对应 sheet>.py`（时间配置/展示规则/销售归属/模板） |
| 改看板页面顺序/标题/输出文件名 | `config/前端渲染/看板展示配置.json` |

## 五、验收（改完必须跑）

```bat
:: 1. 全量测试（含端到端；注意：会真实同步 Excel→JSON 并重写 output/）
pytest tests -q

:: 2. 交付物校验（看板 HTML + 数据总表 + 销售完成度）
python scripts/verify_dashboard.py

:: 3. 大改动（拆模块/改渲染或数据层）额外做"逐字节比对"
python logs/_refactor_verify.py snapshot   # 改之前
python logs/_refactor_verify.py check      # 改之后：看板字节 + 静态资源/6 页模板哈希
python logs/_completeness.py <包名>         # 核对顶层定义是否全部迁入（拆包时）

:: 4. 全产物 A/B 对拍（两棵代码树各跑一遍流水线，逐单元格比较）
::    用法: python logs/_ab_compare.py <A根目录> <B根目录>
```

判据：**看板 HTML 的 sha256 一致**才算"只搬不写"；不一致时先定位差异再继续（`logs/_refactor_verify.py check` 会列出哪一页、哈希差多少）。
⚠️ 数据层改动不要只看测试：曾出现"函数改名/变量写死"导致规则静默失效（异常被 except 吞掉），只有逐字节/逐格比对能发现。
⚠️ **差异要看"分类"不要只看"数量"**：比对出的差异先归类再判断，别急着动手改。例：生成版工作簿与人工编辑版差 2561 格，逐格归类后发现全部是「空字符串 ↔ 真空单元格」（Excel 存过的文件里是 `""`，代码生成的是真空；两者解析结果逐字节一致）——不是缺陷。这条不变量由 `tests/test_config_editor_workbook.py::test_blank_never_written_as_text` 守住（空值不许写成 `None`/`nan` 文本，且 `""` 与真空必须解析成同一结果）。

## 六、配置编辑器工作簿：生成结果字节稳定

**目标**：同一份配置（`config/前端渲染/*.json` + `config/清洗配置/*.json`）生成的 `config/配置编辑器.xlsx` **逐字节一致**，可以用 sha256 判断"生成版有没有被手改过 / 生成器设计有没有走样"。

**实现（`scripts/sheet_style.py`）**

| 工具 | 作用 |
|---|---|
| `new_workbook()` | 建簿：默认字体对齐编辑版（**宋体** —— openpyxl 默认 Calibri 会与编辑版差上万格字体）+ 固定文档属性 |
| `stamp_workbook(wb)` | 固定作者与创建/修改时间（否则每次生成的文件时间戳不同） |
| `canonicalize_zip(path)` | 规范化 zip：条目按名排序 + 固定时间戳，并钉死 `docProps/core.xml` 里被 openpyxl **强制改写成当前时间**的 `dcterms:modified` |
| `save_workbook(wb, path)` | 上面两步的组合，所有写工作簿的地方都用它 |
| `fit_row_height(ws, row, [(文本, 列宽)])` | openpyxl 触发不了 Excel 的"自动适应行高"，长说明文本会被截断 —— 按文本长度/列宽估行数给行高 |
| `clear_blank_strings(wb)` / `canonicalize_workbook(path)` | 原地规范化编辑版：空字符串清成真空 + 固定属性/zip（样式/列宽/行高/冻结/筛选全保留） |

**对齐编辑版的"润色"（固定在生成器里，别再改回去）**：字体宋体；时间配置开始日期列宽 21.909；各表自动筛选覆盖到最后一个数据行（不是只选表头行）；展示规则冻结 `E8`；销售归属/时间配置长备注行按 `fit_row_height` 给行高。

**命令**

```bat
python scripts/config_excel_to_json.py --init        :: 重建工作簿（从 JSON 生成，字节稳定；会覆盖 Excel 侧手工微调）
python scripts/config_excel_to_json.py --normalize   :: 不重建，只规范化现有文件（清空字符串 + 固定属性/zip）
```

**边界（别误判为 bug）**：Excel 每次"保存"都会重写容器（条目顺序/时间戳/它自己的样式表），所以**只要在 Excel 里存过盘，字节就不再等于生成版**——但内容一致；跑一次 `--init` 即可回到字节一致状态（工作簿的编辑内容此时已经由流水线第①步同步进 JSON）。反之 `--normalize` 也会因 openpyxl 重存而有极小差异（如数字格式去重）。

**守住它的测试**：`test_init_template_is_byte_stable`（两次生成逐字节一致 + 生成版不含空字符串单元格）、`test_canonicalize_workbook_inplace`（清空字符串、内容不动、重复规范化字节不变）。
