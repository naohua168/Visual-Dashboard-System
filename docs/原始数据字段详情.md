#### Sheet 1：`收入` — 四源合并清洗

**最终结构**：964行 × 6列

| 列名 | 类型 | 示例 | 来源 |

| 是否为广东公司 | str | 空 | 广东公司数据="是" |
| 是否为深圳公司 | str | 空 | 预留 |

**数据来源（4个来源合并）：**

| 来源 | 文件 | 行数 | 处理方式 |
|------|------|------|----------|
| ① 财务主表 | 收入.xlsx | ~800行 | 按列索引提取4字段 |
| ② 广东公司 | 广东公司.xlsx[收入] | 91行 | 3列直接取用 |

**清理步骤与原因：**

| 步骤 | 操作 | 为什么这样做 |
|------|------|-------------|
| ① 列提取 | 从56列宽表按列索引提取4个字段 | 原始数据是财务系统导出的宽表，只有4个字段有用，其余52列忽略 |
| ② 日期筛选 | 保留 config.json 中 financial 时间范围内的记录 | 只统计当月数据，排除历史/未来数据 |
| ③ 排除内部交易 | 硬编码排除3家公司 | 广东汽车检测中心、中汽院深圳、中汽院湖南是集团内部交易，不计入对外收入 |
| ④ 金额转换 | `fillna(0) / 10000` | 原始数据单位是元，统一转为万元便于展示和计算 |
| ⑤ 事业部分类 | 责任部门名称→映射字典(4类) | 原始数据有50+个部门名，需归并为检测/信息/能源/海外4大类 |
| ⑥ 客户白名单匹配 | 去空格模糊匹配471个客户 | 排除不在白名单中的客户（如临时客户、无效记录），标准化客户名称 |
| ⑦ 公司类型标记 | 初始化为空 | 财务主表不区分公司类型，由广东/湖南公司文件单独标记 |

**广东公司数据处理（特殊）：**

| 步骤 | 操作 | 原因 |
|------|------|------|
| 事业部 | 固定="检测" | 广东公司业务全部归属检测事业部 |
| 公司类型 | 是否为广东公司="是" | 后续17家重要公司分析时需特殊筛选广东公司数据 |
| 金额 | 不÷10000 | 广东公司.xlsx的金额已经是万元单位 |
| 白名单 | 需匹配 | 排除非目标客户 |

**湖南公司数据处理（特殊）：**

| 步骤 | 操作 | 原因 |
|------|------|------|
| 事业部 | 固定="信息" | 湖南公司业务全部归属信息事业部 |
| 公司类型 | 广东="" 深圳="" | 湖南公司既不是广东也不是深圳 |
| 金额 | 不÷10000 | 金额已是万元单位 |
| 白名单 | 需匹配 | 排除非目标客户 |

**运营端数据处理（追加合并）：**

| 步骤 | 操作 | 原因 |
|------|------|------|
| 内部交易过滤 | 按`是否属于内部交易`列="是"排除 | 运营端有明确的内部交易标记列，比硬编码更准确 |
| 金额转换 | ÷10000 | 运营端金额单位是元 |
| 事业部分类 | 已有事业部列→映射4大类 | 运营端数据已有事业部字段，只需简单映射 |
| 客户筛选 | 广东公司全部保留 + 其他白名单匹配 | 广东公司客户不在总部客户名单中，需全部保留 |
| 日期处理 | 统一赋固定日期("2026-01-01") | 运营端时间是"1-4月"文本格式，无法转真实日期 |

#### Sheet 2：`回款` — 四源合并清洗

结构与 `收入` 完全相同，来源对应回款文件。主要差异：

| 差异点 | 收入清洗 | 回款清洗 |

#### Sheet 3：`销售收入` — 从收入按销售规则拆分

**最终结构**：1422行 × 7列（比收入多1列"销售"，行数也增多）

| 列名 | 类型 | 示例 | 来源 |
|------|------|------|------|
| 事业部 | str | 检测 | 继承自收入表 |
| 金额 | float | 34.51 | 拆分后的金额 |
| 客户 | str | 比亚迪汽车工业有限公司 | 继承自收入表 |
| **销售** | **str** | **皮清** | **★ 新增维度（规则匹配）** |
| 日期 | datetime | 2026-06-30 15:18:03 | 继承自收入表 |
| 是否为广东公司 | str | | 继承自收入表 |
| 是否为深圳公司 | str | | 继承自收入表 |

**数据来源：**
```
读 data.xlsx[收入] → 逐行按规则拆分 → 写入 data.xlsx[销售收入]
```

**拆分逻辑（三层优先级）：**

| 优先级 | 条件 | 查找规则 | 示例 |
|--------|------|----------|------|
| ① 第一优先 | 是否为广东公司="是" | 查`广东公司规则` | 广汽集团→夏雪松9.4%+杨贵丰81.2%+李邦金9.4% |
| ② 第二优先 | 是否为深圳公司="是" | 查`深圳公司规则` | 深圳客户→指定销售+比例 |
| ③ 第三优先 | 其他 | 查`其他规则`(380+条) | 比亚迪→皮清40%+黄灿60% |
| ④ 兜底1 | 无匹配 | 查`客户统称名单`分类映射 | 弗迪电池广州分公司→比亚迪电池→周涵林 |
| ⑤ 最终兜底 | 全部无匹配 | 标记"待确认" | 无法归类的客户 |

**拆分示例：**
```
输入一行: 比亚迪 | 检测 | 850万 | 2026-06-30

→ 匹配其他规则:
  规则: {"客户":"比亚迪汽车工业有限公司", "事业部":{"检测":{"销售":["皮清","黄灿"], "比例":{"皮清":0.4,"黄灿":0.6}}}}

→ 输出两行:
  检测 | 340万 | 比亚迪 | 皮清 | 2026-06-30
  检测 | 510万 | 比亚迪 | 黄灿 | 2026-06-30
```

**为什么需要销售拆分？**
- 原始收入/回款表只有客户维度，没有销售人员
- 大屏需要展示**销售人员排名**和**个人达成率**
- 一个客户可能由多个销售共同负责，需按比例分配金额
- 拆分后行数增多（1422 > 964），因为一行可能拆为多行

**总额守恒验证：**
```python
原始总额 = 拆分后总额
if abs(原始 - 拆分后) > 0.01:
    print("⚠️ 收入总额不匹配")  # 允许0.01万元舍入误差
```

### 5.5 旧系统清理的问题与新系统改进方向

| 旧系统问题 | 影响 | 新系统改进 |
|-----------|------|-----------|
| **列索引硬编码** | 源文件列顺序变化→提取错数据 | 改用列名提取 |
| **映射字典写死在代码里** | 新增部门需改代码 | 放 mappings/ 文件夹，改配置不改代码 |
| **内部交易两端逻辑不统一** | 财务端硬编码3家，运营端按列过滤 | 统一为配置驱动 |
| **运营端日期"1-4月"无法精确** | 月度统计时运营端数据全部归到1月 | 保留固定日期，在计算时特殊处理 |
| **客户白名单匹配去空格** | 可能过度匹配（名称相似但不同客户） | 保留机制但增加日志记录 |
| **广东公司金额不÷10000** | 容易混淆单位（有的÷有的不÷） | 配置文件标注单位，统一处理 |
| **销售拆分"待确认"兜底** | 部分客户金额无法归属销售 | 增加日志，定期补全规则 |
| **手工数据和自动数据混在一个文件** | 容易误覆盖手工数据 | 分离 sheets/(自动+手工) 和 mappings/(规则) |
